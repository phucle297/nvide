## Scope interpretation

Create no additional package or binary target. Reuse the existing `nvide` binary target for build-tool dispatch under an `xtask` feature; that feature calls generation code owned by `nvide-rpc-schema` and is absent from normal product builds. This preserves exactly the eight P0-R1 crate targets.

```toml
[alias]
xtask = "run --quiet -p nvide --features xtask --"
```

## Command surface

```text
cargo xtask schema generate
cargo xtask schema check
cargo xtask evidence check --phase 0
```

No other Phase 0 `xtask` commands are approved.

## Toolchain

- Rust runtime: `capnp = 0.26.2`
- Rust generator: `capnpc = 0.26.0`, optional and enabled only by `xtask`
- Schema compiler: Cap'n Proto `1.5.0`
- Compiler source: `https://github.com/capnproto/capnproto/archive/refs/tags/v1.5.0.tar.gz`
- Compiler source SHA-256: `d5ebdf858e9885c33d4b3f765006d68bd66e9b002bf4d607ff4317ef9c1aac6a`

On Linux, `cargo xtask schema generate` and `schema check` bootstrap the compiler when it is absent from `target/phase0-tools`. The Rust command runner invokes these exact programs/arguments and stops on the first nonzero exit:

```text
mkdir -p target/phase0-tools
curl --fail --location https://github.com/capnproto/capnproto/archive/refs/tags/v1.5.0.tar.gz --output target/phase0-tools/capnproto-v1.5.0.tar.gz
sha256sum --check target/phase0-tools/capnproto-v1.5.0.sha256
tar --extract --gzip --file target/phase0-tools/capnproto-v1.5.0.tar.gz --directory target/phase0-tools
cmake -S target/phase0-tools/capnproto-1.5.0 -B target/phase0-tools/capnproto-build -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build target/phase0-tools/capnproto-build --config Release --target capnp_tool
```

Before `sha256sum`, the runner writes `target/phase0-tools/capnproto-v1.5.0.sha256` containing the pinned hash and archive path. Required host tools are `curl`, `sha256sum`, `tar`, `cmake`, and a C++14 compiler; their versions are printed into evidence. The compiler path is exactly `target/phase0-tools/capnproto-build/c++/src/capnp/capnp`. `capnpc::CompilerCommand::capnp_executable` receives that path, and generation fails unless its `--version` output reports `1.5.0`. A cached compiler is reused only after the same path/version check.

## Ownership and determinism

Canonical input is `schemas/nrpc.capnp`. Generated Rust is committed at `crates/nvide-rpc-schema/src/generated/nrpc_capnp.rs` and is never hand-edited. Normal builds consume the committed file and need no schema compiler.

Generation uses repository-relative paths, sorted inputs, no timestamps, and a temporary output before atomic replacement. `schema generate` prints all tool versions and changes only generated output. `schema check` generates into a temporary directory, compares bytes with the committed file, and fails on drift; CI then runs `git diff --exit-code`.

Schema/evidence checks run once on Linux. All four target jobs compile the same committed output. A schema change updates the source, generated code, handshake/compatibility tests, and evidence together. Field numbers are never reused.

## Evidence checker

`evidence check` uses only Rust `std` and no extra manifest. It reads the canonical Phase 0 definitions and `docs/evidence/phase-0.md`, rejects malformed/duplicate/unknown IDs, and enforces this mapping:

| Evidence row | Required references |
| --- | --- |
| `P0-E1` | `P0.1`, `P0.2`, `P0-R1`, `P0-R2`, `P0-A1` |
| `P0-E2` | `P0.3`, `P0-R3`, `P0-A2` |
| `P0-E3` | `P0-R4`, `P0-A3` |
| `P0-E4` | `P0-R5`, `P0-A4` |
| `P0-E5` | `P0-R6`, `P0-A4` |
| `P0-E6` | `P0.2`, `P0-R7`, `P0-A5` |

An ID under the wrong evidence row does not satisfy coverage. The six row IDs plus their required references cover all 21 Phase 0 IDs. Rows may remain `PENDING` during implementation; exit requires exact artifact, command, environment, result, UTC date, and reviewer fields.
