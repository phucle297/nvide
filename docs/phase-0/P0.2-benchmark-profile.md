## Build and clear workload

Build once:

```text
cargo build --locked --release -p nvide -p nvide-core
```

Use a 1920×1080 physical-pixel swapchain, FIFO/vsync, and no workspace or plugins. The event loop continuously requests redraw. Each frame performs exactly one uniform clear and one present with no shaping or scene work.

Launch five fresh processes:

```text
target/release/nvide --phase0-benchmark clear --run-id clear-01 --output target/phase0-evidence/clear-01 --warmup-seconds 10 --measure-seconds 30
target/release/nvide --phase0-benchmark clear --run-id clear-02 --output target/phase0-evidence/clear-02 --warmup-seconds 10 --measure-seconds 30
target/release/nvide --phase0-benchmark clear --run-id clear-03 --output target/phase0-evidence/clear-03 --warmup-seconds 10 --measure-seconds 30

target/release/nvide --phase0-benchmark clear --run-id clear-05 --output target/phase0-evidence/clear-05 --warmup-seconds 10 --measure-seconds 30
```

The private Phase 0 flags are evidence hooks, not public runtime API. Each process terminates after writing a versioned machine-readable bundle. A telemetry failure fails that run; replacing a run requires a new complete five-run bundle.

## Clear calculation and pass rule

Filter compositor events to the target process/surface in the half-open interval `[s, e)` between harness measurement markers on the same OS monotonic clock. Let `t1…tN` be timestamps for actually displayed events and `R` the measured OS refresh period. Require `N >= 2`, `t1 - s <= R`, and `e - tN <= R` so the calculation is defined and a truncated run cannot pass.

```text
displayed_fps = (N - 1) / (tN - t1)
expected_slots = floor((e - s) / R)
missed_rate = max(expected_slots - N, 0) / expected_slots
```

Dropped or superseded presents are excluded from `N` and reported separately; `missed_rate` measures empty display slots, not submitted work that the compositor replaced while maintaining displayed cadence. Every run must have `displayed_fps >= 119` and `missed_rate <= 0.005`. Compute p99 frame interval per run using nearest rank, then report the median plus the worst run: lowest FPS, highest missed rate, and highest p99. All five runs pass independently. Retain every raw event; Tracy/puffin spans are diagnostic only.

## Edit trace workload

Run:

```text
target/release/nvide --phase0-benchmark edit --run-id edit-01 --output target/phase0-evidence/edit-01 --warmup-edits 10 --measure-edits 30
```

Each unique ASCII sentinel carries one trace ID and expected buffer version through UI dispatch, core receipt, version `n→n+1`, viewport emit/receive, shaped glyph inclusion, frame sequence, `SurfaceTexture::present`, and the compositor displayed event. Dispatch the next measured edit only after the preceding trace reaches its displayed event, so permitted viewport coalescing cannot hide a measured edit. Waiting longer than five seconds fails the run and writes the partial bundle instead of hanging. Runtime and compositor events use the same OS monotonic clock. Calibration establishes a one-to-one join by PID, surface/swapchain, frame order, and timestamp. A frame readback containing the sentinel and frame sequence supports the join but is not display evidence alone.

Before the first warmup edit, continuously present the unchanged empty viewport for one second. This stabilization interval is not a trace or sample. For each warmup or measured edit, the sentinel frame remains the correlation target; after it is submitted, NVide performs exactly one untracked identical present so an ETW authority can finalize the target's displayed/dropped state, then stops redraw until the target is acknowledged or its existing five-second deadline expires. The finalizing present cannot replace the target sequence, readback, or timestamp in the trace.

### Display acknowledgement ingress

The bound presentation harness [`tools/phase0-presentmon.ps1`](../../tools/phase0-presentmon.ps1) requires a fresh absolute evidence directory and atomically replaces `<output>/displayed-ack.csv` after its approved compositor authority observes an actually displayed event. The file starts with `pid,frame_sequence,displayed_ns`; the next row contains NVide's decimal PID, the runtime frame sequence, and the authority's OS-monotonic displayed timestamp. Before publishing a row, the harness must filter by the bound PID and surface/swapchain and pass the approved calibration. NVide ignores the preceding frame's still-published row while waiting, requires the finalizing present to complete, requires `present_ns <= displayed_ns <= acknowledgement receipt_ns`, rejects malformed, duplicate, future/out-of-order, or wrong-PID acknowledgements, and does not dispatch the next edit until the matching row arrives. One absolute five-second trace deadline passes unchanged through core request write/response read, renderer/readback polling, and acknowledgement waiting; exhausting it writes a failed partial bundle and a late ACK cannot advance the workload.

After submitting the target, NVide atomically publishes one immutable `<output>/displayed-request-<frame_sequence>.csv` with header `pid,trace_id,frame_sequence,present_ns` and one decimal row. The harness acknowledges only that requested sequence. The exact PresentMon 2.5.1 binding uses `--qpc_time --v1_metrics`, requires its complete v1 CSV header, and converts `QPCTime` plus `msUntilDisplayed` to nanoseconds using the recorded QPC frequency; `Dropped=1` is never display evidence. It requires exactly one row for the bound PID/swapchain within 2 ms of `present_ns`, requires that row to be actually displayed, and revalidates uniqueness against the complete retained capture before success. Zero matches wait; multiple matches, an invalid or duplicate request/trace, a changed swapchain, an extra/missing acknowledgement, or an acknowledgement for any unrequested sequence fail the run. The 2 ms join tolerance is less than one quarter of the eligible 120 Hz refresh period and must be validated by the exit-binding calibration. The harness drains both authority streams, stops the named session on early application exit or failure, and retains raw rows, stderr, hashes, exact commands, and a failure manifest.

For local smoke only, `--unbound-diagnostic` bypasses the displayed-event wait and marks the manifest `UNBOUND_DIAGNOSTIC`; this flag is prohibited in P0-E6. The bound path renders the sentinel on the first line and `frame:<sequence>` on the second line of the captured 64-row viewport strip, requires the sentinel-line pixels to be non-uniform and changed from the preceding edit, and records expected/actual frame sequence plus displayed timestamp. Readback remains supporting correlation data, never a substitute for the compositor authority.

All 30 measured traces must be complete, ordered, version-correct, and joined to an actually displayed event. For the Phase 0 diagnostic mapping, Architecture's `<2 ms` input/edit stage is UI-dispatch→version-increment and `<8 ms` paint stage is viewport-receipt→present-call; report median and p95 for both. P0.2 approval treats these numbers as diagnostic in Phase 0; making them blockers requires a performance-owner measurement artifact and independent performance review.

## Presentation-finalization amendment review

Native PresentMon probing showed that a displayed/dropped decision may be emitted only after a later present. The original wait-without-redraw transition could therefore deadlock even though both sides followed their approved contracts. This amendment adds only the one-second empty stabilization, one immutable display request, and one untracked finalizing present described above. It changes no product/runtime API, benchmark thresholds, measured sample counts, or exit-binding requirement.
