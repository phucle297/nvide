## Findings

### High — `nvide` is not the required thin UI binary

`crates/nvide/Cargo.toml:13` directly depends on `nvide-buffer`, and `crates/nvide/src/main.rs:25` contains a second core state/edit implementation. The Architecture allows `nvide-buffer` dependents `core, syntax, search`, describes `crates/nvide` as the thin UI binary, and ADR-0021 assigns the rope/version owner to the core proof path. The CI allowlist currently blesses this forbidden edge instead of rejecting it. Remove the edge/duplicated core implementation or obtain an accepted architecture change; keep the UI↔core proof across a real child process.

### High — the idle supervisor never schedules heartbeats

`crates/nvide-ui/src/lib.rs:40` sets normal execution to `ControlFlow::Wait`. `about_to_wait` returns while the first one-second interval is still pending (`:171`) and never sets `WaitUntil` or another wake source, so an idle UI can sleep indefinitely and will not detect/restart a dead core. This does not implement ADR-0017/P0-R6. Schedule the next heartbeat wake and leave a runnable check that fails without it.

### High — P0-A4 does not exercise supervised restart

`crates/nvide-core/tests/lifecycle.rs` kills one core and explicitly spawns another itself; it never drives `CoreSupervisor::heartbeat`/`restart`. The two UI tests cover only pure policy helpers. Therefore the claimed forced failure → user-visible degradation → supervised restart/rebind → restart-budget exhaustion evidence is not executable. Add the smallest subprocess test through the actual supervisor path, including the idle heartbeat scheduling behavior.

### High — Windows transport omits binding I/O deadlines

`crates/nvide-platform/src/lib.rs:143` wraps the named-pipe handle in blocking `std::fs::File`; reads and writes at `:199` and `:205` have no deadline. The `5_000` passed to `CreateNamedPipeW` is a named-pipe default wait timeout, not a synchronous `ReadFile`/`WriteFile` timeout. A peer can therefore stall a handshake, partial frame, or write forever on Windows, contrary to ADR-0020 and P0-A4. Implement bounded named-pipe I/O and a Windows runnable timeout check.

### High — accepted buffer trait contract is incomplete

ADR-0005 explicitly requires the Phase 0 trait to cover `insert`, `delete`, `slice`, `line`, `line_count`, and `char_to_byte`. `crates/nvide-buffer/src/lib.rs:111` has no `slice` operation. Add the typed half-open char-range method and boundary/error test required by ADR-0022.

### Medium — cancelled remote streams can emit repeated terminal responses

`Session::response` accepts a cancelled remote stream whenever it remains in `remote_cancelled`, but never consumes/marks a terminal response. Repeated calls can therefore generate more than one `RESP` for the same stream, despite ADR-0020's exactly-one-terminal lifecycle. Record the first terminal and reject subsequent sends, with one lifecycle test.
